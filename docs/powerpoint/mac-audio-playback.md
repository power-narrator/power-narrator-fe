# Mac PowerPoint audio: API research

Research into ways to change Play Across Slides and transfer audio animations on Mac PowerPoint 16.105.3, build 0201, conducted on 2026-10-16. This reference combines findings from the helper-presentation and Ribbon-checkbox investigations. The architectural decision is recorded separately in [ADR 0006](../adr/0006-play-across-slides-is-a-boolean.md).

The observations describe tested API behavior and its limits. They are not guarantees for every PowerPoint version or animation arrangement. Saved presentation state was inspected after native automation and reopening; XML was read for comparison, not edited.

## Alternatives investigated

| Approach                                                                                    | Observed effects and limitations                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Effect `PlaySettings.StopAfterSlides` assignment                                            | Actual value changes in either direction degraded unrelated ink replay and fade animations and some triggers. Moving the assignment before effect movement did not avoid the damage. Reassigning the same value preserved tested unrelated effects, so the reproduced problem was associated with actual changes rather than every assignment. |
| Legacy `Shape.AnimationSettings.PlaySettings`, including creating playback through that API | Actual playback changes produced the same unrelated-animation degradation. Using a higher property path did not bypass the problem.                                                                                                                                                                                                            |
| AppleScript effect and legacy playback setters                                              | Actual changes reproduced the damage observed with VBA setters.                                                                                                                                                                                                                                                                                |
| Replacing the whole `PlaySettings` object                                                   | `EffectInformation.PlaySettings` exposes a read-only object reference. Whole-object replacement was not established as a usable alternative.                                                                                                                                                                                                   |
| `Set existingEffect.Shape = replacement`                                                    | Returned runtime error 438 on the tested build; the existing effect could not be retargeted this way.                                                                                                                                                                                                                                          |
| Configure audio on a temporary slide, then copy/paste the shape or paint its animation      | Preserved tested unrelated effects and saved playback. The method temporarily altered the target presentation’s slide structure.                                                                                                                                                                                                               |
| Configure audio in `Presentations.Add(msoFalse)`, then paint its animation                  | The helper had no editing windows and avoided adding a slide to the target presentation. Unrelated target effects survived, but the setter still reset the helper audio’s own settings and could remove effects or triggers.                                                                                                                   |
| Copy existing animations with `PickupAnimation` / `ApplyAnimation`                          | Retained demonstrated existing playback and custom effects without a playback-changing setter. Effect placement and media/geometry were handled separately in successful probes; see the [copying findings](#animation-copying-findings).                                                                                                      |
| Reconstruct effects after helper configuration                                              | Main Play/Pause/Stop and self/external trigger restoration succeeded for tested arrangements. Some saved sequence-condition and repeat-duration serialization differences remained. Details are recorded under [restoration findings](#restoration-and-trigger-api-findings).                                                                  |
| `ExecuteMso "MediaClipPlayAcrossSlides"`                                                    | Changed playback in both directions, persisted across reopening and preserved tested unrelated effects plus more audio customization than the numeric setter. Some audio command durations and enclosing conditions changed; see [Ribbon findings](#ribbon-checkbox-findings).                                                                 |

## Animation-copying findings

`PickupAnimation` captures a shape’s animations; `ApplyAnimation` applies them to another shape. The unchanged-playback experiments transferred the existing audio’s configuration without subsequent per-effect Timing restoration.

| Aspect                                    | Observation and limit                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Existing playback and custom main effects | The old playback setting, demonstrated delays, repeats, repeat duration, rewind and ordered Play/Pause/Stop effects survived transfer and reopening. Copying the whole animation also carries its playback setting; it is not a way to independently change that setting.                                                                                                                                                |
| Self-click playback                       | Trigger references identified the replacement after the old audio was deleted and the presentation reopened. Demonstrated custom timing survived.                                                                                                                                                                                                                                                                        |
| Global effect order                       | Successful probes explicitly used `MoveTo` to restore original sequence positions. Their final equality does not establish that ApplyAnimation alone preserves position among other shapes’ effects.                                                                                                                                                                                                                     |
| Volume, mute and geometry                 | Nondefault volume, mute, position, dimensions and rotation were retained separately. Final equality does not establish that those properties transfer automatically through ApplyAnimation.                                                                                                                                                                                                                              |
| Zero-delay plain replacement              | A saved enclosing sequence condition changed from 0 to 1 ms in direct reuse and unchanged-helper cases. Per-effect VBA timing summaries appeared unchanged, and save-only controls retained 0. Copying was therefore not universally exact at the full timing-tree level.                                                                                                                                                |
| External-button playback                  | Early direct-copy experiments could not construct the intended trigger through the attempted APIs. Later target-side reconstruction succeeded, while painting a helper’s external relationship lost interactive ownership and became main-sequence On Click. These results do not establish direct-copy success or failure for that relationship. Resolvable shape references alone did not reveal the lost interaction. |

The custom-copying observations included nondefault delay, repeat duration and rewind. A requested fractional repeat count was already rounded during baseline preparation; the experiments did not establish preservation of a fractional value that had not survived preparation.

Copying existing animations into a helper before changing StopAfterSlides did not prevent the reset. The helper’s custom delay and repeat duration became zero, repeat count became the default, and rewind became disabled. Pause/Stop effects could disappear. A vanished self-click effect could leave ApplyAnimation raising Invalid request. Inspection before and after the setter located the loss inside the helper, before the final copy. Painting that result transferred the already damaged state.

## Restoration and trigger API findings

These observations concern explicit reconstruction after the helper setter reset settings. They are distinct from unchanged-state animation copying.

| API or approach                                                                          | Observation and limit                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Main Play `Timing` setters                                                               | Restored tested custom timing lost during a helper playback change. Restoring Timing in the helper did not always preserve enclosing conditions after transfer into differently grouped target effects.                                                                       |
| `MoveTo` and Timing restoration order                                                    | Moving rebuilt effects before restoring Timing resolved a demonstrated enclosing-condition mismatch that remained with the opposite order.                                                                                                                                    |
| Effect and behavior duration restoration                                                 | Restoring Timing alone did not restore every behavior duration. Retaining behavior duration resolved a demonstrated self-click command-duration difference.                                                                                                                   |
| Re-adding Pause/Stop after configuring playback                                          | Retained the configured playback setting in the tested cases. A whole-animation copy was not required to restore those effects.                                                                                                                                               |
| Direct MediaPlay `Timing.TriggerShape` assignment                                        | Returned Invalid request for the tested external-button setup. A Set assignment also encountered runtime error 438.                                                                                                                                                           |
| `AddTriggerEffect`                                                                       | Unavailable in the tested Mac type library; late-bound invocation returned runtime error 438.                                                                                                                                                                                 |
| Converting an existing main Play directly to self-click through TriggerType/TriggerShape | Returned Invalid request. A separately constructed interactive Play after plain main-Play configuration succeeded in tested self-click arrangements.                                                                                                                          |
| Assigning an external trigger to Appear, then changing `EffectType` to MediaPlay         | Retained the external button and media Play command when reconstructed on the target slide. Original button references survived old-audio deletion and reopening. Constructing the relationship in a helper and painting it back instead lost interactive sequence ownership. |

The final reconstruction comparison found exact saved-state matches in most tested cases. Remaining differences included a retained 1 ms enclosing-condition shift and explicit zero repeat-duration serialization on existing mixed main/click effects. Those differences were not evidence of equivalent slideshow behavior.

## Ribbon checkbox findings

The exact identifier is `MediaClipPlayAcrossSlides`. `Application.CommandBars.ExecuteMso` successfully invoked it, and `GetPressedMso` returned its checked/unchecked state on the tested build. Five earlier guessed identifiers returned error 5; those failures did not establish that CommandBars itself was unavailable.

Successful queries and commands used an active editing window in Normal view with the target audio selected. Explicit activation of the Playback tab was unnecessary in that context. The methods reflected global UI state: with no selection or a non-audio selection, a disabled control could report False. A hidden presentation with no editing window could not provide that context. `GetEnabledMso` and `GetVisibleMso` reported availability facts separately from pressed state; invalid-control queries returned error 5.

Actual toggles persisted across reopening. Tested unrelated ink/fade effects, other media, geometry, references and slide structure were retained. Custom Play/Pause/Stop, self-click and external-button trees survived toggles of existing audio. These experiments did not replace that audio, so they did not establish combined replacement-and-toggle behavior.

Observed additional changes were:

| Stored value                    | Observed change            |
| ------------------------------- | -------------------------- |
| Audio command behavior duration | 3888 → 1 ms or 5016 → 1 ms |
| Enclosing delay                 | 5016 → 5000 ms             |
| Enclosing sequence conditions   | Shifts of 1–2 ms           |

These values describe animation commands and sequence conditions, not the audio file’s duration. Their impact on audible or visual playback was not established. Matching-state requests that skipped execution retained exact saved state in the tested cases.

Batched checkbox queries did not change saved content. Restoration of Normal and Slide Sorter context was observed; arbitrary text selections, multiple selections, other window arrangements and slideshow contexts were not established.

## Playback-state API findings

| API or state                                | Observation and limit                                                                                                                                                                                                            |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Numeric StopAfterSlides getter              | Disabled audio returned 83 through one object-reference path and 0 through another, while saved state and the checkbox indicated disabled. Holding an intermediate typed reference did not provide a reliable general cure.      |
| Checkbox and numeric limits                 | Checked state was observed with several finite numeric limits as well as PowerPoint’s usual enabled default. Checked did not mean unlimited playback or automatic start.                                                         |
| `PlayOnEntry=False`                         | Removed Play/media timing in the tested setup while the immediate checkbox remained checked; after reopening it became unchecked. Preparing False through a helper also encountered Invalid request in a separate setup attempt. |
| `PauseAnimation=True` with PlayOnEntry=True | Left the checkbox checked. Its immediate getter returned -1 and its reopened getter returned 0 despite unchanged saved state.                                                                                                    |
| Interactive-only Play                       | Retained checked state after reopening while reporting PlayOnEntry=0 and PauseAnimation=-1. Automatic-main flags and checkbox state were not universally interchangeable across animation arrangements.                          |

A checkbox reading alone did not establish that a valid Play effect remained. Numeric getter values and individual legacy flags also did not provide interchangeable evidence of cross-slide playback.

## Other command routes examined

| Route                                                   | Research outcome                                                                                                                                                                                                                                      |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Play in Background                                      | Published behavior includes automatic start as well as cross-slide playback. It is a broader operation than the isolated checkbox; no independent native preservation comparison was established.                                                     |
| `ActivateTabMso`                                        | Belongs to `IRibbonUI`, not CommandBars. Source research identified a customUI onLoad callback as a route to that object. Native tab-activation support was not established.                                                                          |
| `CommandBars.FindControl` / `CommandBarControl.Execute` | Identified through source research as a possible route if the actual control were discoverable. Exposure of the Ribbon checkbox through that collection was not demonstrated. A workbook Policy ID was not evidence of a usable CommandBarControl ID. |
| Accessibility automation                                | No independent playback-preservation comparison was established.                                                                                                                                                                                      |

## Evidence limits

The investigations compared saved timing/behavior trees, resolved shape and timing references, media properties, geometry, unrelated effects and presentation structure. Per-effect getter summaries alone missed some enclosing-condition changes. Successful reconstruction of selected arrangements did not establish preservation of arbitrary effects, shared triggers, incoming references, stacking order, trim, bookmarks, fades or compatibility with shorter replacement media.

Slideshow attempts started media and advanced slides, but reading the original slide’s player afterward failed with AppleScript error -1700 for both enabled and disabled cases. This was an instrumentation limit, not evidence that playback stopped or continued. Cross-slide audibility, visual fidelity and actual custom-trigger delivery were not established by those attempts. Callable APIs, persistent settings, retained saved state and observed slideshow behavior are separate findings.

## Published API references

Microsoft’s [Mac supported identifier list](https://learn.microsoft.com/en-us/office/vba/office-mac/idmsopowerpointmac) includes `MediaClipPlayAcrossSlides`. The [official Fluent identifier repository](https://github.com/OfficeDev/office-fluent-ui-command-identifiers/tree/b230a0df45036b2d5e8b49ebf368b3f90ada8d63) lists it as a checkbox in the Office 2016 and Microsoft 365 Current Channel PowerPoint workbooks at that recorded revision.

The general [ExecuteMso documentation](https://learn.microsoft.com/en-us/office/vba/api/office.commandbars.executemso) lists buttons, toggle buttons and split buttons; [GetPressedMso](https://learn.microsoft.com/en-us/office/vba/api/office.commandbars.getpressedmso) describes toggle buttons. Native experiments established the behavior reported here for this checkbox. [GetEnabledMso](https://learn.microsoft.com/en-us/office/vba/api/office.commandbars.getenabledmso) and [GetVisibleMso](https://learn.microsoft.com/en-us/office/vba/api/office.commandbars.getvisiblemso) expose separate availability facts. Platform listings do not guarantee parity with every installed build.

The [StopAfterSlides reference](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.playsettings.stopafterslides) describes a writable numeric limit without an animation-preservation guarantee. [EffectInformation.PlaySettings](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.effectinformation.playsettings) exposes a read-only object reference. [Play in Background instructions](https://support.microsoft.com/en-us/powerpoint/play-music-across-multiple-slides-in-your-slide-show-in-powerpoint) describe its broader playback behavior.
