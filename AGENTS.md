### Domain docs

Domain documentation uses a single-context layout. See `docs/agents/domain.md`.

## Code style

### Comments

A comment earns its place by carrying what the code cannot: why a choice was made, a constraint invisible at this line, or a gotcha that reads as a mistake. Let naming and structure carry everything a reader can infer from the code itself.
